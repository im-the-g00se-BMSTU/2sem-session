## 1.    Домены. Модели доменного уровня. Типы доменов. Мосты, клиенты, сервера.

[**Лекция 18 (1:21:21)**](https://youtu.be/MCwwcOCPNBw?list=PLZ8Sl-GV4E_VG4s-ZZ4cvXlCnLyNKWsPa&t=4881)

**Когда имеется большая система, мы разбиваем задачу на домены.**

**Домен -** отдельный реальный, абстрактный или гипотетический мир, населенный отчетливым набором объектов, существующих по характерному наботу правил или линий поведений

**Классификация доменов:**

●      _Прикладной:_ основной домен, который непосредственно решает нашу задачу

●      _Сервисный:_ обеспечивают функции, необходимые для поддержания прикладного домена, всевозможные сервисные функции. Пример: интерфейс.

●      _Архитектурный:_ домен, отвечающий за архитектуру построения системы (один домен на систему); обеспечивает общие механизмы для управления системой и данными (механизмами их передачи). Формализацию начинают с него. Есть уже готовые решения - архитектурные паттерны, которые могут перерастать в целые технологии.

●      _Домены реализации:_ стандартные, библиотечные функции и так далее. Дают возможность лёгкой замены одной реализации на другую. По сути это набор функционала. Примеры: функционал ОС, библиотеки QT, Boost, STL и т.д.

**Мосты, клиенты, сервера.**

Выделяют **2 вида доменов:**

●      Которые **предоставляют возможности - сервера**

●      Которые **используют возможности других доменов - клиенты**

Между доменами существует **мост.** Клиенту не важно, кто предоставляет ему возможности, которые он использует. Серверу не важно, кто использует возможности, которые он предоставляет.

**ПОЛЕЗНО****↓**

**Принцип разбиения доменов:**

когда в домене большое количество классов **(~50 штук)**, его разбивают на подсистемы **по принципу минимума связей** между выделенными подсистемами.

Для **домена** (aka каждой подсистемы):

-        **ДСС -** диаграмма сущность-связь (**информационная модель**)

-        **МВО -** модель взаимодействия объектов (**событийная модель**): можем реализовывать как синхронно, так и асинхронно

-        **МДО -** модель доступа к объектам (**аксессорная модель**): можем реализовывать только синхронно

Если **мы домен разбиваем на подсистемы**, то для домена реализуем:

-        **МСП -** модель связи подсистемы

-        **МВП -** модель взаимодействия подсистем

-        **МДП -** модель доступа подсистем

Получаем соотношение:

-        **ДСС****→МСП**

-        **МВО****→МВП**

-        **МДО****→МДП**
